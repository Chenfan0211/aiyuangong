一、先给结论

产品统一命名为“门店运营系统”，核心交互是“门店运营 Agent”。店长和店员不需要理解复杂报表，通过对话就能查询、解释和推进工作；看板、规则、任务和报表都是 Agent 背后的能力。

原文里最有价值的部分

  • 跨平台经营数据统一口径；
  • 把漏洞拆成店长可执行的最小动作；
  • 任务有负责人、期限、证据和升级；
  • 周报、月报把“结果”与“执行”放到一起；
  • 竞品与内容运营成为后续增长模块。

必须修正的四个表述

  • “打通各个平台”取决于商家授权、开放范围和服务商资格，不能先承诺；
  • “拉多少好评”应改为合规邀请多少真实顾客评价，禁止购买、诱导或伪造评价；
  • “员工完不成直接警告/奖惩”必须由管理者复核，系统只能提供证据和草稿；
  • “流量上涨 20%”只能作为试点目标，必须用对照和归因验证。

二、门店运营 Agent：所有人的统一入口

店长和店员随时打开网页、飞书或企微与 Agent 对话。Agent 先识别“谁在问、能看什么”，再读取门店数据、任务和 SOP，最后给出带依据的回答。

1. 身份店长/店员
2. 意图查询/解释/执行
3. 权限租户/门店/角色
4. 上下文数据/任务/SOP
5. 工具只读/草稿
6. 回答结论+依据
7. 留痕会话/工具/审批
店长 Agent

看全店、问原因、做决策

可问：“今天全店最重要的三件事是什么？”“这个套餐为什么要调整？”“哪项任务逾期了？”“昨天差评有没有闭环？”

可见全店任务与经营诊断；改价、赔付、警告、奖惩、发布仍需审批。

店员 Agent

看本人任务、问方法、交证据

可问：“我今天做什么？”“这个差评该怎么接待？”“完成任务要传什么？”“顾客反馈套餐限制怎么办？”

只看本人任务、操作步骤和非敏感信息；不可查看毛利、工资或全店员工数据。

Agent 必须遵守的回答契约

规则Agent 行为验收
身份优先每次工具调用都由服务端带入 tenant、store、user、role，绝不相信前端自行声明。店员询问毛利返回无权；跨店查询返回 403。
有据可查经营回答附数据日期和来源；任务回答附规则版本与任务 ID。缺数时明确说缺数，不编造经营结论。
最小可见店员只看到本人任务；顾客手机号、工资、密钥不进入模型上下文。敏感字段脱敏测试和提示词攻击测试通过。
分级执行只读可直接答；内部草稿可生成；外发与高风险动作必须审批。未经确认的改价、赔付、警告、奖惩、发布为 0。
会话留痕保存用户问题、Agent 回答、引用来源、工具调用和审批结果。可以从老板周报反查到原始任务和会话。
已提供可运行 MVP：agent_server.py + agent.html。它已支持店长/店员身份切换、角色可见任务、自然语言意图、敏感信息拦截、高风险审批提示和本地会话记录；配置兼容接口的环境变量后，开放式问题可进入大模型。当前身份与经营数据仍是演示配置，不是生产登录或真实平台数据。

三、Agent 背后必须跑通的业务闭环

系统每天不是“发一份报告”，而是完成下面七步，并能从最终结果反查每一步证据。

1. 采集API/导出/POS
2. 对账缺数与延迟
3. 诊断规则优先
4. 派单人/时/目标
5. 举证记录/截图
6. 复核通过/驳回
7. 归因指标是否改善

店长早报

每天 09:00 只给 3–5 件优先事项，写清目标、原因、截止时间与证据；数据缺失时显示“缺数”，不生成假建议。

执行工作台

员工接受、完成、上传证据；超时先提醒，再由区域负责人判断是否升级，不由算法直接处罚。

老板周/月报

同时看经营结果、任务执行率、规则命中率、错误建议率和人工节省时间，奖惩仅使用已复核结果。

四、数据接入：先确认拿得到，再谈 AI

若团队已有工程人员，8 周内部试点按人力折算通常是一个小型产品迭代，不建议先采购昂贵“大模型中台”。平台接口费、服务商费和 PMS 定制费必须拿报价后单列，本方案不凭空填数字。

八、如何证明“流量上涨 20%”

不能用“上线前一个月 vs 上线后一个月”直接下结论。节假日、商圈活动、价格、天气、内容爆款和平台自然波动都会影响流量。至少要保留对照门店或使用分批上线设计。

主指标

平台曝光、门店/套餐详情访问、支付订单、核销订单、核销 GMV。

过程指标

差评首响时长、评价邀请覆盖、任务按时完成率、建议采纳率、有效证据率。

护栏指标

毛利率、退款率、投诉率、误发次数、越权次数、店长额外工时。

建议试验设计

项目要求验收口径
基线期试点前连续 28 天；保存每日原始报表字段完整率 ≥95%，异常日期单独标记。
观察期上线后至少 28 天；同一指标口径不可用“最好的一周”代表全周期。
对照优先选商圈/体量相近且暂未上线的门店比较相对变化，而不是只看试点店绝对变化。
动作日志记录价格、投流、活动、内容、营业时间等干扰因素无法解释的重大变动不得归因给 AI。
成功门槛数据由项目发起人填写并签字建议：曝光或详情访问相对提升 ≥20%，且支付/核销不恶化、毛利不跌破底线。
